# Обучение на Kaggle

Гайд по переносу тяжёлого обучения на бесплатную GPU Kaggle.

## Зачем это нужно

Локальная машина — M1 с 8 GB. Из-за неё дообучение трансформера велось на 38 568 парах в
одну эпоху, и результат ожидаемо оказался в пределах шума (blend `0.602945` против
`0.602527` без него). Доступных пар при этом **11 187 780**. То есть отвергнут был не
метод, а его урезанная в триста раз версия.

Kaggle даёт GPU (обычно T4×2 или P100) и **около 30 GB RAM** против наших 8 — это снимает и
ограничение по обучению, и мучения со сборкой кэшей, которые локально уходят в своп.

Проверьте актуальные лимиты в интерфейсе Kaggle перед стартом: квота GPU (порядка 30 часов
в неделю) и максимальная длительность сессии (порядка 9-12 часов) периодически меняются.

## Ключевое правило: что считать успехом

Успех — **не** высокая метрика самой трансформерной модели. Она и так проигрывает
структурной: в прошлый раз самостоятельно дала `0.449990` против `0.624772` у v13.

Успех — прирост **смеси** на product-disjoint OOD, устойчиво повторяющийся на всех трёх
fold. Ориентир, который нужно превзойти с запасом: прошлый прирост `+0.0004` был шумом.
Значимым считаем прирост, который виден на каждом из трёх fold и превышает разброс между
ними.

Валидация — только `product_disjoint_pair_masks` из `src/hybrid.py`. Случайный сплит здесь
завышает результат в разы: human id-tail даёт `0.652`, а честный OOD — `0.485`.

## Шаг 1. Загрузить данные

Готовить кэши локально не нужно — на Kaggle 30 GB RAM, там это проще. Загружаем сырые
файлы (суммарно ~4.4 GB):

| Файл | Размер |
|------|-------:|
| `assets/items.parquet` | 4.1 GB |
| `assets/items_human.parquet` | 214 MB |
| `assets/matches_llm.parquet` | 105 MB |
| `assets/matches.parquet` | 4 MB |

Через браузер такой объём грузится плохо — используйте CLI:

```bash
pip install kaggle
# Токен: kaggle.com -> Settings -> API -> Create New Token
# Файл kaggle.json положить в ~/.config/kaggle/ (Linux/macOS), chmod 600

mkdir -p /tmp/ecup-data && cd /tmp/ecup-data
cp /Users/kitty/PivoOzon/assets/*.parquet .

kaggle datasets init -p /tmp/ecup-data
# отредактировать dataset-metadata.json: title и id вида "<username>/ecup-matching"
kaggle datasets create -p /tmp/ecup-data --dir-mode zip
```

Датасет делайте **приватным** — данные соревнования.

Обновление после изменений:

```bash
kaggle datasets version -p /tmp/ecup-data -m "update" --dir-mode zip
```

## Шаг 2. Код в ноутбук

Репозиторий приватный, поэтому клонировать его в ноутбук с токеном не стоит — токен
останется в истории ячеек. Два безопасных пути:

- загрузить `src/` вторым Kaggle-датасетом (он маленький) и добавить его в `sys.path`;
- либо вставить нужные модули в ячейки напрямую.

Минимально для дообучения нужны: `src/cross_encoder.py`, `src/hybrid.py`, `src/metrics.py`,
`src/features.py`, `src/train_model.py`.

```python
import sys
sys.path.insert(0, "/kaggle/input/ecup-src")
```

## Шаг 3. Настройка ноутбука

В правой панели ноутбука:

- **Accelerator** — GPU T4×2 или P100;
- **Internet** — включить, если нужны `pip install` или загрузка весов с Hugging Face;
- **Persistence** — Variables and Files, чтобы не терять артефакты между запусками.

Проверка среды:

```python
import torch
print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))
```

Веса базовой модели тянутся с HF при включённом интернете. Если интернет выключен —
загрузите модель третьим датасетом и указывайте `local_files_only=True`.

## Шаг 4. Обучение

Скрипт `src/finetune_minilm.py` уже поддерживает CUDA и bf16 — на GPU он выберет их сам.
Отличия от локального запуска только в масштабе:

```bash
python -m src.finetune_minilm \
  --base-model cross-encoder/ms-marco-MiniLM-L12-v2 \
  --mode compact \
  --max-length 192 \
  --batch-size 256 \
  --epochs 2 \
  --learning-rate 2e-5 \
  --output /kaggle/working/minilm-product-matcher
```

Что менять по сравнению с локальным прогоном:

- **объём** — главное. Вместо 38 тысяч пар берите сотни тысяч или миллионы, сохраняя
  product-disjoint разбиение;
- `--max-length` — 128 режет текст: медиана карточки 82 токена, 90-й процентиль 111, то
  есть на **пару** при 128 без усечения помещается лишь четверть. 192 даёт около 75%;
- `--batch-size` — на T4 отталкивайтесь от 128-256 при длине 192 и уменьшайте при OOM;
- модель — на GPU можно пробовать тяжелее MiniLM-L12, но помните про лимит времени
  инференса в сабмите (ниже).

### Две ловушки, на которые я уже наступил

**Динамический паддинг течёт по памяти.** При `padding=True` каждый батч имеет свою длину,
кэширующий аллокатор заводит пул под каждую форму и растёт без предела. Локально это съело
всю память за 4000 шагов. На CUDA проблема мягче, но лучше сразу добавить
`pad_to_multiple_of=8` — заодно включаются тензорные ядра.

**Чекпоинты обязательны.** Сессия Kaggle обрывается по таймауту, и обучение без промежуточных
сохранений теряется целиком. Сохраняйте каждые N шагов в `/kaggle/working/`.

## Шаг 5. Забрать результат

Из `/kaggle/working/` файлы скачиваются кнопкой Output или через API:

```bash
kaggle kernels output <username>/<kernel-slug> -p ./downloaded
```

Забирайте не только веса, но и **скоры на валидации** — они нужны, чтобы посчитать смесь
локально, не гоняя модель повторно.

## Шаг 6. Проверить, что это вообще стоит включать

Перед тем как класть трансформер в сабмит, проверьте три вещи.

**Значимость.** Прирост смеси должен повториться на всех трёх OOD-fold. Разовый выигрыш на
одном fold — это шум, ровно на этом в прошлый раз и остановились.

**Размер.** Архив ограничен 5 GB, образ 15 GB. MiniLM-L12 весит порядка 130 MB и проходит
свободно; reranker на 600 MB в прошлый раз был признан невыгодным по соотношению
цена/качество.

**Время.** Это главный риск. Лимиты: Check 1 мин, Public 6 мин, Private 13 мин, а скорость
работы решения жюри оценивает наравне с местом в лидерборде. Сейчас чисто структурный v13
занимает Private `411.7с` из `780с` — запас есть, но не бесконечный. Baseline организаторов
на MiniLM-L12 при длине 256 укладывался в 18.5 мин из 20 на все стадии, то есть эта модель
близка к потолку. Обязательно прогнать `.venv/bin/python -m src.emulate_run --stage all`
и убедиться, что Private проходит.

Важно: локальные замеры времени валидны **только** на незанятой машине. Параллельный запуск
проверки и обучения на 8 GB уводит систему в своп и искажает результат в разы — у нас
Private показывал `3175с` вместо реальных `409с`.

## Что ещё разумно обучить на GPU

Дообучение кросс-энкодера — не единственный кандидат:

- **Переразметка LLM.** Правилами разрешены только модели с открытой лицензией, а код
  разметки должен быть воспроизводимым. Сейчас используются 572 749 LLM-пар из 11 187 780;
  качественная переразметка спорных пар может дать больше, чем новый трансформер.
- **Bi-encoder для эмбеддингов как признаков.** Дешевле кросс-энкодера на инференсе:
  эмбеддинги товаров считаются по одному разу, а не по разу на пару.
