## 2026-08-14 — v6: усиленные парные признаки + расширенный selective hybrid

Реальный прогон v5 дал **0.2507679239** (v4 → v5 подтвердил направление). Основной шаг
v6 — 19 новых устойчивых парных признаков поверх прежних 36 (итого 55 структурных + 2
TF-IDF = 57). Все признаки — по-прежнему отношения между карточками (не запоминание
товаров), считаются на CPU, IDF берётся из товаров текущего прогона (как и TF-IDF):

- **IDF-взвешенное сходство названий** (jaccard/containment): редкие токены (модель,
  артикул в названии) весят больше частотных («для», «чехол»);
- **сигнал редчайшего токена**: макс. IDF среди общих и среди несовпавших токенов,
  флаг «редчайший токен каждой стороны присутствует у другой» — ловит модель/вариант;
- **числовое совпадение**: jaccard/containment/disjoint по множеству чистых чисел;
- **char-4 и char-5 n-граммы** названия (тоньше прежних char-3);
- **IDF-взвешенное сходство значений атрибутов**;
- **асимметрия лишних токенов** (одна карточка — уточнённый вариант другой);
- **совпадение первого/последнего токена** названия.

Честная валидация (те же три split-а), только новые признаки, human-only бустинг:

| Split | v4/v5 human-only | v6 признаки | Прирост |
|-------|-----------------:|------------:|--------:|
| random | 0.575826 | **0.605968** | +0.030142 |
| id-tail | 0.569930 | **0.600757** | +0.030827 |
| name-group | 0.574035 | **0.602755** | +0.028720 |

Прирост стабилен по всем split-ам и улучшил все 20 категорий.

### Расширение selective LLM hybrid до 9 категорий

С новыми признаками LLM-сигнал стал полезен шире. Проверка per-category delta (hybrid −
human-only, вес ручных = 10) на обоих split-ах дала **9** категорий с положительной
дельтой на обоих: прежние 4 (Бытовая техника, Бытовая химия, Продукты питания,
Строительство и ремонт) плюс **Галантерея и аксессуары, Дом и сад, Красота и гигиена,
Электроника, Ювелирные изделия**. Заметный вклад — слабые категории (Ювелирные
+0.0158/+0.0060, Электроника +0.0096/+0.0026).

| Split | human-only v6 | 4-cat hybrid | **9-cat hybrid v6** |
|-------|--------------:|-------------:|--------------------:|
| id-tail | 0.600757 | 0.601971 | **0.603622** |
| random | 0.605968 | 0.607233 | **0.608574** |

Итог v6 (9-cat hybrid) против прошлой продовой (v5, id-tail 0.570745): **+0.0329**
локально. Артефакт `models/pair_boost_hybrid.npz` (2.02 MiB) включён по умолчанию;
human-only `models/pair_boost.npz` (57 признаков) сохранён для отката через

## 2026-08-12 — v5: selective LLM hybrid

После появления полного `assets/items.parquet` (13 397 761 товар) стала доступна
предоставленная LLM-разметка. Из всех 13 parquet row group собрана ограниченная выборка
572 749 пар по всем 20 категориям; большие производные кэши остаются в игнорируемом
`output/` и не входят в сабмит.

Проверка на ручном `id-tail`:

| Источник обучения | Macro PR-AUC |
|--------------------|-------------:|
| Human-only boosted | **0.569931** |
| LLM, threshold 0.5 | 0.455161 |
| LLM, только target=0 или target≥8/9 | 0.454331 |
| Hybrid, human weight=2 | 0.561825 |
| Hybrid, human weight=5 | 0.569412 |
| Hybrid, human weight=10 | **0.570995** |

LLM содержит переносимый сигнал, но его шум не позволяет заменять ручную разметку.
Полный hybrid с весом 10 слегка улучшил id-tail, но ухудшил random с 0.575826 до
0.574154. Поэтому LLM включён только в категориях, где delta положительна на обоих
split-ах: **Бытовая техника, Бытовая химия, Продукты питания, Строительство и ремонт**.

Оценка selective hybrid из фактических per-category результатов:

| Split | Human-only v4 | Selective hybrid v5 |
|-------|--------------:|--------------------:|
| random | 0.575826 | **0.576374** |
| id-tail | 0.569931 | **0.570745** |

Ручные примеры в hybrid-категориях имеют вес 10. Создан отдельный артефакт
`models/pair_boost_hybrid.npz` (1.97 MiB), он включён по умолчанию; human-only
`models/pair_boost.npz` сохранён для мгновенного отката через `PAIR_BOOST_MODEL_PATH`.
Check прошёл за 1.6с, формат и полнота результата корректны. Полный Public/Private имеет
ту же структуру и число деревьев, что уже проверенный v4.

## 2026-08-12 — v4: устойчивый категорийный бустинг

Реальный прогон v3 показал **0.2294975974** против **0.2047051459** у TF-IDF:
абсолютный прирост +0.0247924515, относительный +12.1%. Направление подтвердилось, но
прирост оказался меньше ожидаемого по случайному holdout.

### Диагностика локальной валидации

Добавлены режимы `id-tail` (валидация на последних ID внутри category/target) и
`name-group` (одинаковые нормализованные названия не пересекают train/valid), а также
кэширование дорогих признаков. Категорийная логрег-модель оказалась стабильной:

| Split | TF-IDF | Global logreg | Category logreg |
|-------|-------:|--------------:|----------------:|
| random | 0.321473 | 0.468055 | 0.540709 |
| id-tail | 0.322393 | 0.464176 | 0.536861 |
| name-group | 0.321438 | 0.467914 | 0.538866 |

Таким образом, разрыв с leaderboard не объясняется простой утечкой по ID или повторным
названиям. Возможные причины — другая доля положительных пар (PR-AUC напрямую зависит от
prevalence) и более общий сдвиг закрытого распределения.

### Новый production-кандидат

Обучены отдельные `HistGradientBoostingClassifier` по 20 категориям: 250 деревьев,
31 лист, `min_samples_leaf=40`, `l2=2`. Нелинейная модель улучшила все три режима:

| Split | Category logreg | Boosted | Прирост |
|-------|----------------:|--------:|--------:|
| random | 0.540709 | **0.575826** | +0.035117 |
| id-tail | 0.536861 | **0.569931** | +0.033070 |
| name-group | 0.538866 | **0.570381** | +0.031515 |

Деревья перенесены в `models/pair_boost.npz` (1.96 MiB); production-инференс реализован
вручную на NumPy и не использует sklearn/joblib. На контрольных 1000 строках максимальное
расхождение со sklearn decision function — 3.5e-6. Метод `boosted` включён по умолчанию,
старые `supervised` и `tfidf` доступны через `MATCH_METHOD`.

## 2026-08-11 — v3: обучаемый категорийный скорер

Получен результат реального прогона прежнего TF-IDF-решения: **0.2047051459**. Он заметно
ниже локальных 0.3197 и подтвердил, что прямое лексическое сходство плохо переносится на
закрытые тяжёлые пары.

Реализован компактный supervised-скорер:

- 38 отношений между карточками: сходство названий и символьных 3-грамм, совпадения и
  конфликты одноимённых атрибутов, артикулов, числовых токенов и брендов, два TF-IDF
  косинуса;
- отдельная логистическая модель для каждой из 20 категорий плюс общая fallback-модель;
- нелинейные пороговые преобразования признаков перед линейным слоем;
- переносимый артефакт `models/pair_logreg.npz` размером 24 KiB; production-инференс
  использует только NumPy и не зависит от версии sklearn/joblib в Docker-образе;
- `supervised` был методом по умолчанию для прогона v3; теперь оставлен как fallback
  рядом с `MATCH_METHOD=tfidf`.

### Честная holdout-валидация

Фиксированный стратифицированный split 80/20 (`seed=2026`), товары почти не повторяются
между парами (711 304 уникальных товара на 365 654 пары), поэтому утечка по товарам
пренебрежимо мала.

| Метод | Macro PR-AUC |
|-------|-------------:|
| TF-IDF на тех же holdout-строках | 0.321473 |
| v3 supervised | **0.540709** |

Прирост: **+0.219236** абсолютных. Улучшены все 20 категорий; диапазон v3 по категориям
на holdout — от 0.3532 (Одежда) до 0.7815 (Детские товары).

## 2026-08-11 — v2: прямые эмбеддинги + вывод о «потолке» прямых методов

**Цель этапа:** проверить, даёт ли семантика (эмбеддинги) прирост над лексикой, всё ещё
без обучения классификатора.

### Что попробовали (единый sample 20k, для честного сравнения)
| Метод | Macro PR-AUC | Скоринг (Mac) |
|-------|-------------|---------------|
| `tfidf` (слова 1-2 грамма) | **0.3503** | 3.6с |
| `tfidf_wc` (слова + char_wb 2-5, вес 0.5) | 0.3481 | 27.9с |
| `embed` (e5-small, косинус) | 0.3368 | 281с (MPS) |
| rank-ансамбль tfidf+embed (лучший, w=0.7) | 0.3522 | — |

### Ключевые выводы
- **Семантика не бьёт лексику.** Bi-encoder косинус (e5-small) даёт 0.337 — ниже tfidf.
- **Char n-граммы не помогли** при весе 0.5; лексический сигнал уже насыщен словами.
- **Ансамбль почти не помогает** (+0.002): лексика и семантика здесь избыточны, не
  комплементарны.
- **Все прямые методы упираются в ~0.32–0.35.**

### Почему так (важно для стратегии)
Случайный скорер даёт macro PR-AUC ≈ **0.261** (доля положительных пар). Наши прямые
методы (0.32 на полном сете) — лишь **скромный подъём над случайным**. Причина: пары —
это **тяжёлые негативы** из Retrieval-этапа (лексически похожие, но РАЗНЫЕ товары). Их
косинусная близость (что лексическая, что семантическая) высокая → плохо разделяются.
→ Реальный прирост даст **обучаемая модель** (cross-encoder / классификатор), способная
ловить тонкие различия. Это следующий большой шаг (v3), отложенный по условию.

### Решение по продовому методу
Продовый прямой метод остаётся **`tfidf`** (лучший из прямых, самый быстрый, без torch в
рантайме). Код `embed`/`tfidf_wc` оставлен как доступные методы для будущих экспериментов.

### Инфраструктура
- Добавлены методы `tfidf_wc` и `embed` (ленивый импорт torch/sentence-transformers).
- `EMBED_MODEL`/`EMBED_PREFIX`/`EMBED_DEVICE` — конфиг эмбеддера (для офлайна путь к
  вшитым весам).
- Локально e5-small на MPS медленный (~14 мс/пара) — это артефакт устройства; на H100
  быстро. Тайминг v2 локально не показателен по скорости, только по корректности.

## 2026-08-11 — v1: прямое решение (TF-IDF), без обучения

**Цель этапа:** понять стартовую позицию на лидерборде без обучения и релабелинга,
наладить локальное тестирование.

### Сделано
- Скелет решения в `src/` + entry point `run.py` и `metadata.json` (запуск как в примере:
  `python -u run.py --items_path … --matches_path … --output_path …`).
- Метод скоринга v1 — **TF-IDF косинусная близость** текстов товаров (`name` +
  развёрнутые `attributes`). Векторизатор обучается unsupervised на товарах прогона →
  офлайн, без весов, детерминированно.
- Локальная оценка `src/local_eval.py`: считает macro PR-AUC по 20 категориям + тайминг с
  экстраполяцией на Public/Private.
- Гарантия: предсказание для **каждой** входной пары (нет текста → скор 0), порядок пар
  сохраняется. Проверено на срезе в 1000 пар без `target` (как в тесте).

### Данные (факт)
- `matches.parquet`: 365 654 пар, `target` 0/1 (25.7% положительных).
- `items_human.parquet`: 711 304 товара, 20 категорий.
- **Покрытие пар товарами — 100%** по всем 20 категориям (~18k пар/категория) → честный
  локальный размеченный сет, зеркалящий тестовую структуру.
- `items.parquet` (4.1GB) отсутствует — полный корпус недоступен (см. [ASSETS](ASSETS.md)).

### Результат v1 (локально)
```
MACRO PR-AUC = 0.3197   (tfidf, полный сет 365 654 пары, 20 категорий)
MACRO PR-AUC = 0.3512   (tfidf, sample 40k — для сверки, чуть оптимистичнее)
```
Разброс по категориям (полный сет): от **0.13** (Обувь) до **0.63** (Детские товары).
Слабые категории (Обувь, Аптека, Мебель, Ювелирные изделия ≈ 0.13–0.17) — где названия/
атрибуты плохо различают товары чисто лексически → главные кандидаты на прирост от
семантических эмбеддингов (v2).

### Тайминг (этот Mac, CPU)
- Скоринг: ~0.18 мс/пара.
- Экстраполяция: Public ~21с (лимит 360с), Private ~50с (лимит 780с) — **огромный запас**.
- Вывод: по скорости v1 проходит с колоссальным запасом → есть бюджет на гораздо более
  тяжёлый метод (эмбеддинги/cross-encoder).
